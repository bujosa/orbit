# Orbit 0.2.1 · Early access

This patch keeps a reconnection queue intact when its next Mac becomes unreachable.
The connection center explains how to restore reachability and offers **Retry
connection**, **Skip this account**, and **Stop queue**. Network recovery alone
never resumes sign-in. Unreachable Macs also have a read-only retry in the fleet
dashboard and connection center.

**Refresh** now imports newer access checks saved by `orbitctl`, preserving their
original timestamps and newer in-memory results. It sends no model requests and
does not erase a prior authentication rejection merely because a check is old.

The setup guide explains how Orbit and Uso work side by side: Orbit checks fleet
access and official sign-in; Uso shows remaining AI usage on an individual Mac.

## Compatibility and installation

- Apple Silicon, macOS 14+, Node.js 22.13+, and official provider CLIs.
- Agent snapshot and managed-login schema remain version 1. Existing 0.2.0 agents
  remain compatible; use the bundled update action when installing matching agents.
- Quit Orbit before replacing its app bundle. Private inventory, provider sessions,
  and verification history remain outside the app and are retained.
- The downloadable build is ad hoc signed and not notarized. This remains an
  early-access release; Developer ID distribution and automatic service recovery
  are future work.

## Validation scope

Queue recovery, ordering, explicit skip/stop, and verification-cache merging have
regression coverage in the existing core suite. Native UI and live fleet status
are checked separately. Completed account-owner browser approval and MFA still
require interaction on the provider's official page; simulated lifecycle tests
do not establish that a live login completed.
